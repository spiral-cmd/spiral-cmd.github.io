Position Paper — Infrastructure Decision

Should OpenClaw upgrade Forgejo to v16?

📅 3 September 2026 ✍️ CC 🔖 ops/forgejo · ops/infra
Verdict

Do not upgrade to v16. Stay on v15 LTS. Watch v17 in October.

The motivation — "use new project functionality" — is based on a false premise: the Project REST API, auto-move on close, and live board updates are not shipped in v16. All three are open issues or unmerged WIPs. Additionally, v16 is non-LTS with support expiring in seven weeks; v15 LTS runs through July 2027.

Context: The kanban board script failure that surfaced this question (forgejo-kanban-move.sh CSRF crash on Forgejo v15's changed HTML structure) has already been fixed this session. The upgrade impulse was in part a workaround to a problem that no longer exists.

3 — What v16 Actually Ships

For completeness: v16 does ship real improvements, primarily around Forgejo Actions and pull request workflows. None are relevant to the project/kanban motivation.

  • ✓ Actions workflow API — endpoints for listing/downloading/deleting artifacts, per-job log download, run cancellation endpoint
  • ✓ Manual workflow prioritization — control execution order of queued runs
  • ✓ Authorized Integrations — JWT-based cross-system authentication for Actions
  • ✓ Multiline PR review comments — Shift+click drag to select a range (API + UI)
  • ✓ Code search — zoekt integration for full-text search across repos
  • ✓ OIDC dynamic group mapping — attribute-based group assignment on login
  • ✓ Granular repo watch preferences — separate watch settings for Issues, PRs, Releases

Of these, Actions API improvements are the only category with relevance to OpenClaw (Cato/io currently have no artifact management). Worth noting for future evaluation, not a sufficient reason to upgrade on a non-LTS branch with weeks remaining.

4 — Breaking Changes & Upgrade Risk

If the upgrade were to proceed, three breaking changes require explicit remediation. One is high risk for the current Docker deployment.

  • Reverse proxy trusted proxies High risk Default REVERSE_PROXY_TRUSTED_PROXIES = * is removed. Any Docker Compose setup using ENABLE_REVERSE_PROXY_AUTHENTICATION=true must set trusted proxy addresses explicitly in app.ini or lose authentication passthrough silently. OpenClaw's Forgejo is accessed via localhost:3000 with no reverse proxy currently, so this is low impact now — but must be confirmed before any future nginx/traefik addition.
  • SSRF hardening — git redirect following disabled Low risk http.followRedirects=false is now the default for git mirrors. Repos that point to URLs which redirect (renamed Forgejo repos, moved GitHub repos) will fail to mirror. OpenClaw has no mirrors configured, so no immediate impact.
  • EXIF stripping removed Cosmetic AGPL dependency removed; images uploaded to issues/wikis no longer have EXIF metadata stripped. No operational impact for OpenClaw.

5 — Recommendation

Recommended Actions
  1. 1
    Stay on v15 LTS. No action required. Current Docker tag codeberg.org/forgejo/forgejo:15.0 is supported through July 2027. The kanban script bug that surfaced this question is already patched.
  2. 2
    Watch PR #13714 (Project API). This is the correct prerequisite for replacing the cookie-session kanban workaround. Monitor Codeberg for merge — it may land in v17.
  3. 3
    Evaluate v17 in mid-October 2026. v17 ships October 15. If the Project API merges into it, the upgrade case becomes strong: proper REST endpoints replace the cookie-session script entirely, and v17 may qualify as LTS. Run the upgrade evaluation then as a fresh brief.
  4. 4
    Do not depend on auto-move or live updates in any planning horizon. Issue #773 has been open for years. Build IIV-close automation around the existing API + label workflow, not on features with no committed timeline.
