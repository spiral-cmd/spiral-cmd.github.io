01 / CONTEXT
ops/#335 — 2026-10-02

Multi-Agent Workspace Architecture

Shared vs. isolated — where do files go?

The Problem

Config says per-agent workspaces. Reality says shared workspace. Agents bootstrap from stale identity files. File panel links are dead. Every operational write lands in the wrong place.

The Root Cause

The 2026-08-24 workspace change created a split: agents.defaults.workspace = shared root, agents.entries.*.workspace = per-agent dirs. Two authorities, one filesystem.

02 / OPTIONS

Three Options on the Table

Option A

Per-Agent Workspaces

Each agent owns its full workspace. Operational files migrate into per-agent dirs. OpenClaw's documented design intent.

Risk: 6× script/bible duplication, constant sync overhead. Half-done migrations are worse than none.

Option B

Single Shared Workspace

All agents read and write one dir. Bootstrap files merged into one shared AGENTS/SOUL/IDENTITY set.

Risk: Identity collision guaranteed. Six distinct protocols don't compose into one coherent file.

Option C ✓ VERDICT

Shared Root + Per-Agent Bootstrap Subdirs

Shared workspace/ for operational files. Per-agent workspace/agents/<id>/ for identity bootstrap. One workspace root, clean identity isolation.

Score: 5/6 models recommend C. Bootstrap hook is the documented integration path.

04 / PRINCIPLE

The Core Insight

Two file classes. Two sharing models. Conflating them is the root cause.

Operational State

Shared by Default

Scripts, cron definitions, bible, inboxes, handoffs. Agents coordinate through these. Six copies = six divergence bugs waiting to happen.

Lives at: ~/.openclaw/workspace/

Identity State

Exclusive by Default

AGENTS.md, SOUL.md, IDENTITY.md, PROTOCOL.md, MEMORY.md. Each agent's protocol, role, and behavioral constraints are non-composable.

Lives at: workspace/agents/<id>/

"Operational files are shared by default; identity files are exclusive by default; exclusivity is enforced by hook, not convention. The shared root is the only workspace."
Decision rule — to be written into ops/#335 as the governing invariant
