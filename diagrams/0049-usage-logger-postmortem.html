Failure 1 of 5

The brief was under-specified

Sub-step ack requirements and Codo-fail escalation paths were missing from the original brief. Both had to be patched mid-flight.
What was missing

No sub-step ack protocol (Polo acks after each named sub-step). No explicit escalation path if Codo is unavailable. No delivery-channel contract (a2a-bus vs to-cc.md vs mailbox).

What happened instead

Martin flagged missing acks 15 min into C2. CC patched protocol mid-chunk. Codo routing broke and CC had no pre-planned pivot — took 3 failed attempts to confirm Codo was broken, then pivoted to Polo-direct.

The fix (§5.3)

Sub-step ack protocol added to a2abible.md. Every chunk brief must now name required acks (C2-a, C2-b, etc.) and explicitly specify the delivery channel. Escalation path (Codo unavailable → Polo-direct) must be in the brief before it is sent.

Lesson

A brief that doesn't name its failure modes is incomplete. Write the escalation path before you need it.

Failure 3 of 5

Infrastructure not validated pre-build

Codo's model routing was broken before the build started. CC included Codo in the plan without confirming it could actually run inference.
The Codo/zai problem

agent.json set siliconflow/deepseek-ai/DeepSeek-V3.2 but the gateway's global provider resolved to zai/glm-5.1 at spawn — which had no credits. Every Codo session spawned and immediately failed.

3 attempts wasted

C3-a, C3-b, C3-c all attempted via Codo-chain before Polo confirmed the routing was broken. 3 failed attempts = 3 wasted time slots, each with a 20-min timeout.

Root cause

Global provider in openclaw.json overrides per-agent agent.json at spawn time. A pre-build infra check would have caught this in 30 seconds: spawn Codo, run a 1-token inference, confirm response.

Fix

Disable zai failover (Martin vai). Codo now uses SiliconFlow directly. Pre-build infra validation added as a mandatory CC step before any Codo-involved chunk is released. Chipped as task_5d112eb9.

Failure 4 of 5

a2a-bus messages expired silently

Polo's acks to agent:cc:main all expired — CC session rejected injection. C3 was done at 21:39; CC didn't know until 22:46.
The injection failure

Polo sends via a2a_send(to="agent:cc:main"). The CC session rejects injection with "not found or at capacity." Message expires. From CC's perspective: silence. Polo thinks ack was delivered.

67-minute blind spot

C3 completed at 21:39 BST with full PASS verdict. CC discovered this only at 22:46 by reading a2a-mailbox.db directly. During those 67 minutes CC was sending ~idf signals on a completed chunk.

The multi-channel confusion

Three delivery channels active simultaneously: a2a-bus (Polo), mailbox.sqlite (io), to-cc.md (protocol). CC's monitor watched only mailbox and to-cc.md. Polo's channel was invisible.

Working fix

On every silence alert, CC queries a2a-mailbox.db directly before escalating. Polo a2a-bus injection fix is a separate tracked item — session key format mismatch.

Failure 5 of 5

Session creation ≠ inference success

CC read a Codo session spawn event and declared "Codo is working." The session spawned, then immediately failed over to zai. The declaration was wrong.
What CC said

"Codo session spawned 1 min ago — it is working." This was stated with confidence in the channel. Polo's parallel test at the same moment was C3-a-FAIL.

Why it was wrong

Session creation (spawn → session file written) and inference success (first token returned from the target model) are two separate events. The gateway can spawn a session, route to zai, fail, and the session record still exists. CC read the first event and inferred the second.

Rule going forward

Never declare an agent "working" from session existence alone. Verify with a 1-token inference result or an explicit ack from Polo citing the model name and first response.

Root Cause

Reactive supervision throughout

Every problem in this build was caught by Martin running /csn or by CC checking a2a-mailbox after the fact — not by CC's own monitoring.
  • Brief sent without sub-step acks — Martin flagged it
  • Silence threshold breached — Martin ran /csn
  • Second breach — Martin ran /csn again
  • Codo declared working — wrong; Polo proved otherwise
  • C3 complete — CC discovered 67 min late via manual DB read
  • C4/C5 deadlines breached — CC sent ~idf only after Martin said "~idr"
Pattern

CC announced rules it didn't enforce. Thresholds were stated in channel but not backed by automated checks that actually triggered escalation. Martin had to provide the enforcement pressure that should have come from CC.

Required shift

Supervision must be proactive: timed checks fire automatically, CC polls all delivery channels on silence, wrong calls are corrected immediately not post-hoc. Martin should be informed of exceptions, not asked to find them.

Protocol Changes

What changes going forward

Three concrete protocol additions and two verification rules that address the root cause directly.
Brief standards
  • Name all required sub-step acks in every brief (C{N}-a, C{N}-b…)
  • Specify delivery channel explicitly (a2a-bus + sermo echo)
  • Write the Codo-unavailable escalation path before briefing
  • Run a 1-token inference check before any Codo chunk
Silence monitoring
  • 20-min threshold is hard — ~idf fires automatically, not on Martin's prompt
  • On every silence alert: query a2a-mailbox.db before escalating
  • Monitor must cover all channels: mailbox, to-cc.md, a2a-bus
  • Sermo update every 5 min during active build; kill + ~idr at 10 min silence
Verification rules
  • Session existence ≠ inference success; verify with model-name ack
  • Agent "fixed and verified" is a claim — check live state before relaying to Martin
  • CIV gate: CC explicitly ACKs each chunk-complete before next chunk releases
  • Forgejo issue must be in every brief — no exceptions
